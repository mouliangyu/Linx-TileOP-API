# TileOP 接口手册结构规范

本规范确定全量 TileOP 接口手册的组织方式，适用于所有操作页及其公共参考。它取代编写计划中早期的章节模板和“角色表置于声明之前”的安排。它规定文档结构，不新增算子语义或硬件限制；已有页面尚需按此规范整理。

## 目录与查询入口

`TileOpReference/` 保持打平。每个公开操作使用一个同名文件，完整收录该名字的重载；不为 Reader、Writer、Local、Shared 或参数变体另外拆出操作页。不同公开操作名各有自己的页面。README 提供分类与名称导航、目标版本及公共参考入口；分类不产生子目录。

公共类型、Options、Reader、Writer 和各族 `*Rules.md` 与操作页同层。设计讨论、来源核对、覆盖状态及编译验证记录放在目录外。手册正文直接描述新设计，不混入旧接口兼容、迁移流程或“拟议支持”的表述。

## 操作页固定结构

所有操作页使用以下顺序和六个二级标题。简单操作可以每节只有一段，但不能把数节内容堆入“操作数角色”，也不能为样章另设一套顶层结构。

| 位置 | 标题 | 必须回答的问题 |
| --- | --- | --- |
| 页首 | `# 操作名`，一句话功能与元信息 | 操作做什么？头文件、命名空间是什么？目标版本链接到哪里？ |
| 1 | `## 声明与重载` | 完整签名是什么？有多个重载时如何选择？ |
| 2 | `## 参数与操作数角色` | 各参数怎么填，默认值是什么，哪些接受 Tile、Reader、Writer 或 GM 视图？ |
| 3 | `## 操作语义` | 计算或地址公式是什么？返回什么、修改什么、产生哪些副作用？ |
| 4 | `## 合法组合与限制` | 哪些类型、布局、形状、存储和别名组合合法？有哪些特殊执行条件？ |
| 5 | `## 示例` | 如何构造一次完整调用，输入前提和可观察结果是什么？ |
| 6 | `## 公共规则与相关接口` | 本操作适用哪些公共合同，相关操作和索引在哪里？ |

函数声明只放在“声明与重载”，不得藏在角色表章节。页尾的相关接口与返回索引之后不再追加参数或语义章节。

### 声明与重载

完整列出模板参数、约束、函数参数、返回类型和默认值。不用宏、占位省略号或“其余类似”替代签名。多个重载先用小表说明选择条件，再逐一声明；复杂操作可以按 Local/Shared 或其他真实区别设置三级标题。

同一页不再另列一份“普通 Tile 基线签名”。普通 Tile 与分片由公开协议及逐参数支持表解释。确有不同公开重载时，必须给出各自的选择条件。

### 参数与操作数角色

模板参数与函数参数分别说明。函数参数表包含参数名、输入输出方向、含义与单位、默认值及其含义；每个公开参数都有对应条目，包括 G、PEMask、Options 和物理维度参数。没有某个参数的操作不得从族文档复制该参数行。

Tile 类操作数另用一张角色表列出参数、协议、普通 Tile、Reader 片段、Writer 输出描述的可用性。GM、标量和 Options 明确其自身类别，不强行套入 Tile 协议。按重载存在差异时，在表中标出适用重载。

角色表全页只保留一份。分片特有的坐标、范围或发布要求放在“合法组合与限制”的三级小节，不再重复支持矩阵。通用 Readable/Writable 定义链接到 OperandRoles；Reader/Writer 生命周期链接到各自页面。

### 操作语义

使用公式、索引关系或明确文字描述本操作。区分数学结果、物理存储、有效区域和库侧元数据。说明是否读取旧目标、是否广播或转换、返回值与输出对象的关系，以及 GM 更新、原子性或发布等可观察效果。

仅描述本操作：TABS 不介绍 LOG 的定义域，TMUL 不保留 SUB/DIV/REM 的参数次序说明。共享数值规则用精确链接引用。

### 合法组合与限制

给出能判断调用合法性的 dtype 配对、存储位置、布局、形状关系、容量、对齐及别名条件。需要组合关系时使用配对表，不能用互不相关的类型集合暗示任意组合都合法。

公共规则只链接；本操作专用条件在这里展开。动态错误、诊断或未定义行为只有在合同有依据时才能写入，不把旧 wrapper 的限制、实现缺失或资料缺口推导为新接口禁令。

复杂操作仍使用同一顶层结构。例如矩阵的四 PE 分工和布局配对、TIMG2COL 的协作行分配及 Writer 阶段要求放在本节三级标题下；参数字位域和 Options 字段的取值含义放在参数节，实际计算效果放在语义节。每项信息保留一个定义位置，其他位置引用它。

### 示例

每个操作页至少提供一个本操作的具体调用示例。定义所用类型和参数；外部输入可用函数形参提供，但须写清形状、初始化及访问权限前提。说明可观察结果或效果，不用孤立的 `OP(dst, src)` 代替示例。

重载或专用行为无法由一个示例说明时增加示例，不机械复制完整 kernel。公共示例可作为补充，不能替代操作页自身示例。是否实际编译、运行及对应环境记录在覆盖记录中，不暗示未验证代码已通过验证。

### 公共规则与相关接口

集中列出适用的公共规则和相关接口；正文中的具体条款也可就近链接到同一个定义。引用应指向实际章节，不能只用“满足 ISA 要求”代替可查询的合同。返回索引是页面最后一个导航项。

## 公共规则的唯一归属

| 信息 | 定义位置 | 操作页保留内容 |
| --- | --- | --- |
| Tile 类型、单位、维度取得、通用计算维度选择和库侧元数据 | CommonTypes.md | 参数及默认值、适用规则链接、确有差异的专用绑定 |
| Readable/Writable 与计算视图身份 | OperandRoles.md | 本操作逐参数角色表 |
| read、first/middle/last/single、finish、迭代器生命周期 | Reader.md、Writer.md | 本操作的分片特有要求 |
| 各族共享的类型配对、布局和运算合同 | 对应 `*Rules.md` | 本操作的公式、参数与专用限制，精确链接共享表 |
| Options 字段、枚举和编码 | Options.md 及对应公共参考 | 本操作接受哪些字段、默认值和生效条件 |
| ISA 来源、历史决定、未决项及实现验证状态 | 目录外的设计、审查和覆盖记录 | 必要的来源链接，不复制讨论过程 |

每个操作的函数声明以同名操作页的“声明与重载”为唯一维护位置。公共页通过调用示例解释协议，并链接该操作的完整声明。公共类型、协议及其成员声明由对应公共页维护。公共规则描述适用操作集合及共同合同。

普通参数的含义、单位和默认值可以在操作页直接列出，这是查询所需信息；维度优先级、元数据更新等完整算法不能在多页各写一遍。操作专有规则若不同，必须明确适用范围及公共规则中不适用的部分，不能靠页面顺序决定优先级。

## 公共参考页结构

公共参考不强行套用操作页六节，但同类页面保持一致。类型与协议页按用途、声明、成员或参数、语义与约束、示例、相关接口组织。族规则页按适用操作、共享合同、组合表及专用子类规则、公共示例、相关接口组织。

公共页不能变成第二份操作手册。新规则先确定归属再修改；同名操作页有入口，公共页有唯一完整定义。

## 整理与验收

按上述模板整理所有操作页，包括早期样章及后补的 TLEA、TSTORE_ATOMIC 系列，不只调整 TADD。重排过程中保留已确认的接口合同；发现语义冲突时单独记录，不用改章节的机会自行补出限制。

完成标准：

- 每页六个二级标题名称、顺序一致；专用扩展使用三级标题。
- 声明全部位于声明节，参数说明覆盖每个公开参数及重载差异。
- 每页只有一份角色表，不存在重复 Reader/Writer 支持说明。
- 不含其他操作的残留段落、失效模板参数名或不存在的参数。
- 通用算法只有一个定义位置，各页引用一致；没有公共页与操作页相互循环定义。
- 每页有本操作的具体示例，类型、输入前提及结果完整。
- 所有正文在页尾导航之前；本地链接、锚点及代码围栏有效。
- 结构检查通过仅代表组织正确；合同真实性、接口覆盖和编译验证分别核对，不能相互替代。
